# 実機で待機・睡眠表現を動かす準備

通常の制御には、同梱の `crane_x7_ros`（`crane_x7_control`とMoveIt設定）を使います。
読み取り専用のSDKノードは同時起動しません。

2026-11-02時点で、ユーザーによる実機の活動度変化の確認と、以前のシミュレーションによる
眠気モデルの確認は完了しています。その後、公式構成でhomeまで動いたことをユーザーが確認し、
自作構成でも待機・睡眠姿勢への移動成功を実機ログで確認しました。
揺れの開始時に停止したため、揺れの継続と今回の修正後の実機動作は未検証です。
ユーザーから「動作指示は送らないで」と指定されています。エージェントはログ・状態の読み取りと
ローカルの修正・テストだけを行い、実機起動・再起動・enable・軌道送信はユーザーが操作します。
RealSenseについてユーザーから、公式の`CRANE-X7_with_RealSenseD435.pdf`と同じ取り付けのはず、
との情報がありました。公式図を確認し、現行D435モデルの44.5 mm・17.5 mmのオフセットと整合することを
オフラインで確認したため、標準取り付け仕様を前提に進めます。実物の寸法実測・固定具やケーブルの
完全な形状確認は行っていません。初回起動ではRVizの姿勢・カメラ位置を実物と比較します。

参照図面（2019-09-19、RT Corporation）:
[CRANE-X7_with_RealSenseD435.pdf](https://github.com/rt-net/crane_x7_Hardware/blob/master/Drawing/CRANE-X7_with_RealSenseD435.pdf)
（確認したPDFのGit blob: `50c8875b2357906d66fb397c49a6fb3258165d9b`）。
図面の寸法基準とURDFのフレーム原点は異なるため、図の全寸法が単一の`origin`へそのまま入るわけではありません。

## 読み取り専用でモデルを比較する（動作開始の前）

写真でRealSenseが手首外側に付いていることを確認し、その後、上記の公式取り付け図が示されました。
先端のカメラ・固定具が他のリンクに近い姿勢に見えるため、自動動作の前に比較します。
次のプレビューは通常の制御ドライバ・MoveIt・表現を起動せず、
実測したアーム7軸の角度をRVizの候補モデルへ反映します。モーターへの書き込みはありません。
この読み取り専用プレビューは、上記の実機制御起動とは別です。

既存の読み取りlaunchも終了してから実行してください（USBを二重に開かないため）。

```bash
cd /home/kaito/4s_robodesign_jubilant
source /opt/ros/jazzy/setup.bash
source install/setup.bash
export ROS_DOMAIN_ID=88
ros2 launch ./src/arm_control/hardware_preview.launch.py port:=/dev/ttyUSB0
```

RVizの視点を回し、実物と同じ方向から手首に対するカメラの取り付け位置・向き・張り出しを
比較します。画面のカメラは標準D435の候補であり、写真から校正したモデルではありません。
このプレビューだけで正確な寸法や経路の安全性まで確認できるわけではありません。
固定具の形状と寸法は別途確認し、必要なら衝突モデルへ追加します。
グリッパーは読み取り対象外なので、指の一部が未表示になる場合があります。
TFとrobot_descriptionも`/hardware_observation/`配下へ分けています。
実機なしで表示を試す場合は`source:=mock`を追加できます。終了はCtrl+Cです。

## 起動前に確認すること

- 読み取り専用launch、Gazebo、別の制御ドライバ、DYNAMIXEL Wizardを終了する。
- アームの固定と設置姿勢を確認し、RealSenseとケーブルを含む経路から人・物を離す。
- カメラと固定具の位置・大きさを実物とモデルで照合する。このlaunchは標準D435モデルを
  候補として読み込む。D435iや独自固定具の場合も、形状・位置を合わせてから使用する。
- 今回の簡易設置面は`base_link`基準z=-0.01 mに上面がある3 m四方の箱。
  実物の設置面に合わせる必要がある。机上の物体やケーブルは自動検出しない。
  固定具も自動的にはモデル化されない。
- 停止操作をする人を決める。ROSのキャンセルは非常停止装置ではない。

開始姿勢の衝突エラーが出た場合は開始操作を繰り返さず、実物の接触を確認します。
2026-11-02の再起動後に、グリッパー指bと土台側の肩との接触が報告されました。
ユーザーも実物の接触を確認。読み取り専用の`/check_state_validity`でも`valid=false`、
同じリンク対の衝突が継続しました。モデルの侵入深さは約5.1 mmで、これは実物の実測値ではありません。
この時点の関節情報は肩約−22.06°、肘約−148.62°で、以前の睡眠姿勢と異なっていました。
接触がある開始姿勢から自動で抜け出す指令は生成しません。衝突判定も除外しません。
通電中に手で押し続けず、支持を確保して制御を終了・電源OFFにし、通常の取り扱いに従って
接触を解消した初期姿勢へ戻す必要があります。接触箇所や関節の隙間へ指を入れないでください。

実機ドライバは**起動時に現在位置を可動域内へ制限して書き込み、PIDゲインを設定し、
トルクを有効にします**。表現動作が無効でも、ドライバ起動自体は読み取り専用ではありません。
可動域外の姿勢では起動時の位置書き込みで動く可能性があります。
終了時は低いPIDゲインへ変更する実装なので、終了後の姿勢保持にも注意が必要です。

今回は`realsense2_description`も使います。カメラ映像のドライバは自動起動しません。

## モデル確認後の起動と開始

以下は取り付けモデルと設置面を照合した後に使う手順です。
今回の標準取り付けという前提で進める際は `camera_model_confirmed:=true` を明示します。
別の固定具・位置へ変えた場合は、この前提を引き継がず改めてモデルを確認します。

端末1（通常の実機ドライバ・MoveIt/RViz・活動度・眠気・グラフ・表現を起動）:

```bash
source /opt/ros/jazzy/setup.bash
source install/setup.bash
export ROS_DOMAIN_ID=88
ros2 launch ./src/arm_control/hardware_activity.launch.py port:=/dev/ttyUSB0 camera_model_confirmed:=true
```

表現ノードは無効の状態で起動し、待機姿勢への移動も行いません。
引数を省略した場合の既定値`camera_model_confirmed=false`では開始操作も拒否します。
RVizに出る姿勢が実機の姿勢と対応していること、RealSense・固定具が対応していることを確認します。
この比較が済むまでは、開始サービスやRVizのExecuteを使わないでください。
実物と明らかに違う場合は動作を開始せず、モデルを修正します。

端末2（ROS環境と同じdomainを設定）:

```bash
source /opt/ros/jazzy/setup.bash
export ROS_DOMAIN_ID=88
ros2 service call /sleep_expression/enable std_srvs/srv/SetBool '{data: true}'
```

この開始操作後は次のように動きます。

1. MoveItで肩20°・肘−120°・手首−80°の待機姿勢へ一度移動する。
2. 眠気0.6以上で、肩10°・肘−120°・手首−70°の睡眠姿勢へ移動する。
3. 肩を±3°・6秒周期で揺らし、手首を逆向きに動かす。

眠気はlaunch起動時から増えます。開始操作時点ですでに0.6以上なら、
待機姿勢への到達後、すぐ睡眠姿勢への移動に進みます。
外部刺激は未接続なので自然には覚醒せず、揺れを繰り返します。
表現の指令角速度を活動度から差し引く点はシミュレーションと同じです（実機での確認は未実施）。

実機では姿勢移動のMoveIt速度倍率を0.03、加速度倍率を0.02に下げています。
実機制御周期は50 Hz（20 ms）です。初回の実機ログで200 Hz（5 ms）に対して
読み取りが11〜16 msかかっていたため、実機launchから周期を上書きします。
変更後に警告が解消するかは再起動後の実測で確認します。
すべての送信軌道で0.25 rad/sの上限、有限値、可動域、時刻順、開始姿勢とのずれを検査します。
MoveItの経路計画と、揺れの各サンプルの衝突確認を継続して使用します。
関節情報・眠気が1秒途絶えると実行中の動作へキャンセルを要求します。

表現だけを停止する場合:

```bash
ros2 service call /sleep_expression/enable std_srvs/srv/SetBool '{data: false}'
```

停止要求で軌道のキャンセルを要求し、自動的に元の姿勢へは戻しません。
トルクは変更しません。計画待ちやアクションの受理待ちだった場合にも、
停止後の送信を拒否するか、遅れて受理された軌道へキャンセルを要求します。
起動端末のCtrl+Cは一式を終了しますが、前述のドライバ終了時のゲイン変更を伴います。

## 開始姿勢が可動域外の場合

14:16の計画ログでは肩tiltの実測値が1.60915 rad（約92.20°）、モデルの上限が
約1.60570 rad（92.00°）で、開始姿勢が約0.20°範囲外のためMoveItが停止しました。
値は超過量ではなく現在角度です。ずれの原因（負荷による偏差、ゼロ点など）は未特定です。
URDFの上限拡大、測定値の丸め・書き換え、MoveItの判定無効化は行いません。

実機用ノードは開始時と計画直前に7軸の実測角度を確認し、範囲外なら軸名・現在角度・
許容範囲を表示して拒否します。失敗時は表現を無効にし、眠気の更新で再試行しないようにしました。
原因を解消してから明示的な開始操作が必要です。変更後はlaunchを再起動してください。

初期姿勢を手で変える場合は、実機の通常の取り扱い手順に従い、アームを支えてから
制御launchを終了し、電源を切った状態で行ってください。通電中に力で押し戻さないでください。
肩を上限に接した状態から余裕のある姿勢へ戻し、カメラ・配線・他のリンクとの接触を避けます。
再起動後も同じずれが続く場合は、ゼロ点・取り付け・保持時の偏差を確認します。

開始姿勢の拒否と失敗後の無効状態維持を含む19テスト、既存睡眠表現7テストが成功しました。
修正後の実機動作は未検証です。

## 睡眠姿勢への移動成功後、揺れの開始姿勢で停止した場合

実機ログで待機姿勢と睡眠姿勢への移動成功を確認しましたが、揺れの先頭で
「軌道の開始姿勢が現在姿勢から離れています」と停止しました。
停止後の`/joint_states`では、肘の目標−120°に対して約−124.63°（差−4.63°）でした。
コントローラの成功通知が、全関節で0.03 rad以内の一致を保証するわけではありません。
失敗瞬間の全関節値は記録されていませんが、この実測値で旧処理の同じ停止を再現しました。

実機の揺れ軌道は、先頭を実測姿勢に合わせ、目標との差を前半周期で5次多項式により
減衰させるよう修正しました。各軸の差が5°を超える場合はこの接続を行わず停止します。
6秒周期なら最初の3秒で補正が消え、その後は元の揺れ軌道です。
目標の睡眠中心を実測値で上書きしないため、周期ごとの中心角度のずれは蓄積しません。
接続区間を含む全サンプルの可動域・速度・MoveIt衝突確認と、送信直前の0.03 radの開始差検査は保持します。
開始差エラーには軸名・実測値・軌道先頭・差を表示します。

変更後の反映にはユーザーによるlaunch再起動が必要です。自動的には動作を開始しません。
肘の保持時の偏差の原因（負荷・調整・ゲインなど）は未特定であり、今回PIDなどは変更していません。
実測値での再現、先頭/終端、中心の保持、大きな差の拒否、補正区間の速度/可動域検査を含め、
関連43テストが成功しました。実機での修正後の揺れは未検証です。
